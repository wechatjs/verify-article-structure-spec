二、Step 1 — 谁会被挑出来（候选规则）

① img
所有 <img> 无条件入队（跳过 ProseMirror-separator 光标占位图）
② table → th
表只测 thead th，每个 th 一个候选（key = pIdx_th0/1/2），不再下钻单元格
③ 固定宽度的普通元素
非 img/svg 且 inline width 有值且不匹配 auto|100%
④ 段落本身（特殊）
段落节点也入队，标记 overflowOnly:true —— 只测溢出，不测居中/宽度差
豁免：节点自身或任一祖先带 data-ignore-width → 整个跳过（段落级候选单独判断，子节点照常跑）。
量的是渲染值不是声明值：Step 1 只读 style 字符串做粗筛，真正的数字在 Step 3 测。

三、Step 2 — 沙箱怎么搭

离屏但参与布局
position:fixed; left/top:-9999px; visibility:hidden
→ 用户看不见，但 getComputedStyle / getBoundingClientRect 数值照常正确
强制容器样式
.rich_media_content * { max-width:100% !important; box-sizing:border-box !important; word-wrap:break-word !important }
模拟公众号正文容器的压制行为
图片宽度兜底
优先等真实加载用 naturalWidth（5s 超时）；
没加载出来 → inline width → data-w → HTML width 属性；
三者皆无 → 塞 1×1 透明 SVG，防止 rect 坍缩成 0×0
调试模式
debugSandbox:true 时 sandbox 停在视口内、红虚线框、不自动移除，方便手查

四、Step 3 — 三屏实测（核心）

容器（screenConfigs.width） 被测元素 rect 溢出部分
指标算法含义
computedWidth Math.round(rect.width) 真实渲染宽度（非 CSS 声明值），是后面所有比较的基准
widthRatio computedWidth / config.width 元素占容器的比例，用来识别「被容器压满」的正常响应式
isHorizontallyCentered |leftGap − rightGap| ≤ 1 用减法判对称（加法判的是「是否铺满」，判不出居中）
isOverflowing (left < pRect.left−1 ‖ right > pRect.right+1) && !isCentered 1px 亚像素容差；对称居中的溢出不算（视为刻意视觉效果）
isHeightZero rect.height < 1 高度坍缩，配合 height 规则用
换屏后 await sleep(100) 再量，等浏览器完成重排；节点靠 sandbox.querySelector('[data-violation-id="…"]') 回查克隆体。

五、Step 4 — 跨屏怎么判定

判据条件说明
hasWidthDiff任一屏 |computedWidth − base| > 10px以第 0 屏（585）为基准
hasRatioDiff任一屏 |widthRatio − baseRatio| > toltol 默认 0.2；若某屏 ratio 恰好 =1 则收紧到 0
isNormalResponsive每屏要么 ≈ 基准，要么 |widthRatio − 1| < 0.1被容器压满 = 正常响应式，豁免
hasOverflowDiff各屏 isOverflowing 不一致大屏不溢出小屏溢出 → 命中
hasCenterInconsistency有的屏居中、有的屏不居中固定 px 宽 / margin 偏移的典型症状
规则 A · 不同屏幕下宽度差异
hasWidthDiff && hasRatioDiff && !isNormalResponsive
#1.4.3 固定 px 宽没做响应式适配
规则 B · 居中布局不一致
some(居中) && some(不居中)
#1.4.1 移动端与编辑器预览不一致
规则 C · 存在溢出问题
hasOverflowDiff（或 overflowOnly 节点任一屏溢出）
#1.4.2 margin/padding 偏移、transform 位移
放过的情况
三屏都居中都被压满宽度恒定且比例恒定
段落级 overflowOnly 只跑规则 C，不跑 A/B

一句话总结：量的是 getBoundingClientRect().width 在 585 / 677 / 375 三档容器下的真实渲染值， 再用「绝对差 10px + 占比差 0.2 + 居中/溢出一致性」三个维度跨屏比对出结论。CSS 里写的 width 只用于 Step 1 粗筛，不参与判定数字。
