核心思想：不读代码里写的 line-height 数值，而是让浏览器真实排版一遍，用尺子量出「行与行实际离多远」。所以继承的、动态的、混排的样式全都逃不掉。

STEP 1

找出要检查的段落

遍历整篇文章的 DOM，凡是块级元素且直接包含文字的（<p> / <div> / <section> / <h1-h6> / <li> / <td>），都列为「受检段落」。纯图片容器、空标签跳过。

STEP 2

把文章关进「沙箱」——一台虚拟手机

检测不能只在代码字符串上做（读不到继承样式），也不该污染用户页面。做法：造一个屏幕外的隐藏 div，把文章 HTML 塞进去，让浏览器真实排版。再依次把沙箱宽度调成三种手机屏宽，每个宽度都量一遍——因为换行不同，叠字可能只在某一档宽度下出现。

沙箱 = 隐藏的 div
真实排版，人看不见
585px iPhone 标准内容宽 —— 量一遍
677px 大屏 / PC 内容宽 —— 再量一遍
375px 小屏手机 —— 再量一遍
同一篇文章在三档宽度下换行位置都不同，
叠字可能在某一档才出现，所以要各量一次
STEP 3

用 Range API 当尺子：问浏览器「每块文字在哪」

对每个段落调用 range.selectNodeContents(p) + getClientRects()。浏览器会返回每个文字片段的矩形（位置 top / 高度 height）——相当于让排版引擎自己把尺子量好报给我们。这一步能拿到 CJK 和英文混排、嵌套 span、行内图片的全部真实几何信息，这是只读 CSS 字符串永远做不到的。

STEP 4

归并出「真实行数」：y 区间重叠超过一半 = 同一行

拿到一堆片段矩形后，两两比较垂直方向的重叠：重叠部分超过较矮矩形高度的一半 → 它们在同一行。这样混进大字号、上下标（top 会偏移）也不会数错。

frag A top100 frag B top100 → 第 1 行
frag C top142 frag D top142 → 第 2 行
✓ 同一行（重叠 > 50%）
大部分区间叠在一起 → 归并成一行
✗ 相邻两行（重叠 < 50%）
只擦到一点点边 → 是两行，行距就是它俩的间距
STEP 5

算「平均行进距离」，对照阈值下结论

公式只有一条：平均行距 = 内容总高度 ÷ 真实行数。这个数就是「敲回车后光标每次往下走多远」。拿它和 0.95 × 字号（16px 字号即 15.2px）比较。

正常段落

行距 = 108 ÷ 5 行
     = 21.6px
21.6 ≥ 15.2 → ✅ 通过

真叠字段落

行距 = 70 ÷ 5 行
     = 14.0px
14.0 < 15.2 → 🚨 报「请核实」
阈值 15.2px = 0.95×16

另有一条直通规则：计算出的 line-height 恰好为 0（行框完全塌缩，图片无缝拼贴常用写法）时，只要段落里有真实文字就直接报，不用进公式。

一句话总结

  1. 不信任代码里写的数字——把文章塞进隐藏沙箱，让浏览器真实排版三档宽度；
  2. 用 Range API 量——每个文字片段的真实位置和高度，排版引擎就是尺子；
  3. 按垂直重叠归并行数——重叠过半算同行，大字号/上下标都不怕；
  4. 行距 = 总高 ÷ 行数，低于 0.95×字号就提示人工核实——这个阈值刚好贴住 16px 汉字的真实墨水高度（14.8px），低于它墨水就开始相交。
